# 新規 float32 HDR 可逆圧縮器 ML 強化版 設計計画

> 古典手法だけの計画 ([PLAN.md](PLAN.md)) は「Blosc 越え (5.5x)」が現実目標だったが、
> ML を活かせば **7-10x ratio @ 100+ MB/s** を狙える。本文書はその拡張計画。

## 1. ML を入れる根本的な理由

**圧縮 = 予測** という等式 (シャノン以来 70 年、Hutter Prize の前提) より:

```
圧縮率 ≒ 予測器の質
予測器の質 ≒ モデルがデータ分布をどれだけ学習できているか
```

古典 MED predictor は 1990 年代に手作業で設計された 3-neighbor の固定ルール。
これに対し、学習された予測器は:

| 観点 | MED 予測器 | 学習予測器 |
|---|---|---|
| 文脈サイズ | 3 ピクセル (N, W, NW) | 任意 (5x5, 7x7, dilated) |
| 適応性 | なし | データ分布に最適化 |
| 出力 | 単一値 (点推定) | 確率分布 (= 残差の不確実性も表現) |
| HDR 特化 | 不可 | 訓練で可能 |
| 内容認識 | なし | 空/質感/エッジを区別可能 |

**理論的には**、学習予測器の方が確実に小さい残差を出す。問題は速度と実装の難しさ。

## 2. ML 圧縮の到達点 (文献 + 推定)

### 既存研究 (RGB 8-bit が中心)
| 手法 | 対象 | 結果 (vs PNG) | 復号速度 |
|---|---|---|---|
| **L3C** (Mentzer 2019) | RGB | 2x 小さい | 数 MB/s (CPU) |
| **Practical FRLLIC** (Mentzer 2018) | RGB | 30 % 小さい | 数 MB/s |
| **iWave++** (2021) | RGB | wavelet + 学習 | 10 MB/s 程度 |
| **DLPR** (2023) | RGB | SOTA | 不明 |
| **HALIC** (2023) | RGB | SOTA | 30 MB/s |

### float32 HDR 向け
- **公表研究はほぼ皆無** ── 我々が取り組めるニッチ
- 物理シミュレーション系 (SZ, ZFP) は近接研究だがロッシー中心
- **新規性の余地が大きい**

### 我々の現実的目標
| 観点 | Blosc bitshuf | 古典ハイブリッド (前計画) | **ML 版 (本計画)** |
|---|---|---|---|

## 3. アーキテクチャ案 (4 つの ML 統合戦略)

### 戦略 A: 「古典 + 学習残差モデル」 (低リスク、中ゲイン)
```
古典予測 (MED) → 残差 → [学習モデルが残差分布を予測] → rANS
```
- 古典がベースライン保証 → ML はその上で残差を学習
- 学習モデルは小型 (1-2 MB) で十分
- **期待 ratio: 6-8x**
- **実装難度: 中** (古典実装が動いてから ML 追加)
- **デコード: 100-300 MB/s** (古典予測は速い、ML は分布推定だけ)

### 戦略 B: 「自己回帰ピクセル予測器 (PixelCNN 系)」 (高リスク、高ゲイン)
```
各ピクセル ← 因果マスク CNN が条件付き分布を出力 → ANS 符号化
```
- PixelCNN++, PixelSNAIL 等の縮小版
- 完全に学習ベースの予測 (古典なし)
- **期待 ratio: 7-10x**
- **実装難度: 高** (学習が大変、デコードが逐次的)
- **デコード: 10-100 MB/s** (沼)

### 戦略 C: 「階層的予測 (L3C 風)」 (中リスク、高ゲイン)
```
原画像 → 1/2 → 1/4 → 1/8 → 1/16 を予測子ネットワークで生成
各レベルを上位レベルから条件付きで rANS 符号化
```
- 並列復号可能 (レベルごと)
- L3C は実証済みアーキテクチャ
- **期待 ratio: 7-10x**
- **実装難度: 中-高**
- **デコード: 30-200 MB/s** (レベルごと並列)

### 戦略 D: 「ハイブリッド (古典前処理 + 学習エントロピーモデル)」 ★ 推奨
```
[1] 可逆色変換 (R, G-R, B-R)
[2] log-magnitude 変換 (HDR を LDR-like ダイナミックレンジに)
[3] 古典 MED 予測 (高速、決定論的)
[4] 残差を bitshuffle (Blosc から流用)
[5] ★ 学習エントロピーモデルが文脈から残差分布を予測
[6] rANS で符号化 (予測分布を確率モデルとして使う)
```

- 段階 1-4 は古典 (堅実、SIMD で高速)
- 段階 5 だけが ML (軽量モデルで OK)
- **期待 ratio: 7-9x**
- **実装難度: 中**
- **デコード: 100-300 MB/s** (古典部分が支配的)
- **エンコード: 100-500 MB/s** (全段階並列可能)

★ **戦略 D を推奨** ── ML のゲインを取りつつ、決定論性と速度を確保

## 4. 戦略 D の詳細設計

### 4.1 全体パイプライン

```
入力 float32 W×H×C
    ↓
[段階 1] 可逆色変換: (R, G, B) → (R, G-R, B-R)
    ↓
[段階 2] log magnitude 変換: x → sign(x) * log2(1 + |x|)
    ↓ (これで HDR の dynamic range が 30 dB に圧縮)
[段階 3] MED predictor (整数 ulp 域で実行)
    ↓ → 残差 r[i,j]
[段階 4] 残差を 4 byte plane に bitshuffle
    ↓ → bit-plane streams
[段階 5] ★ Causal CNN (1-3 MB, ANE で実行)
    各位置の 7x7 因果文脈から
    残差分布 p(r | context) を予測
    出力: 256-class softmax × 4 planes
    ↓
[段階 6] rANS 符号化 (予測分布を確率モデルとして使う)
    ↓
圧縮出力
```

### 4.2 ML モデルのアーキテクチャ案

```python
# 軽量 Causal CNN (~2 MB at fp16)
class HDRResidualModel(nn.Module):
    def __init__(self):
        super().__init__()
        # 入力: 4 byte planes × 7x7 因果マスク = 196 channels
        self.conv1 = MaskedConv2d(mask='A', in_ch=4, out_ch=32, kernel=7)
        self.res1 = ResBlock(32)
        self.res2 = ResBlock(32)
        self.res3 = ResBlock(32)
        # 出力: 4 planes × 256 class
        self.head = MaskedConv2d(mask='B', in_ch=32, out_ch=4*256, kernel=1)
    
    def forward(self, byte_planes):
        # byte_planes: (B, 4, H, W)
        x = self.conv1(byte_planes)
        x = self.res1(x)
        x = self.res2(x)
        x = self.res3(x)
        logits = self.head(x)  # (B, 1024, H, W)
        return logits.reshape(B, 4, 256, H, W)
```

- パラメータ数: 約 50 万 (fp16 で 1 MB)
- 演算量: 1 ピクセル ≒ 50K MAC → M4 ANE で 1 メガピクセル < 5 ms
- 訓練データ: 数千枚の HDR (Poly Haven 全部 + 自前データ)

### 4.3 ANE で何が変わるか

| プラットフォーム | 戦略 D の推定 |
|---|---|
| Mac (M3/M4, ANE 使用) | enc 200-500 MB/s, dec 100-300 MB/s |
| Mac (CPU のみ) | enc 50-100 MB/s, dec 20-50 MB/s |
| Linux x86 (CPU) | enc 30-80 MB/s, dec 15-40 MB/s |

→ **Apple Silicon に限れば、ML 統合が「速度コスト」にならない可能性が高い**

これが最大の差別化要素。汎用 ML 圧縮は「遅すぎる」が、ANE 前提なら古典並みの速度が出る。

### 4.4 訓練データセット

| ソース | 枚数 | サイズ | 入手 |
|---|---|---|---|
| Poly Haven HDRI (4K) | 700+ | 80+ GB | CC0 |
| sIBL Archive | 100+ | 数 GB | CC |
| Laval Indoor HDR | 2000+ | 大きい | 学術用 |
| MIT-Adobe FiveK (HDR 風) | 5000 | 30 GB | 学術用 |
| 自前撮影 / 自前レンダリング | 任意 | 任意 | 自由 |

**最低 1000 枚、理想 5000 枚** で訓練。データ拡張 (クロップ、フリップ、露出変動) で実効 10 万枚。

## 6. Phase 6-7 の詳細 (ML の山場)

### 訓練の現実
- GPU: 1 台の M3 Max (Metal) で訓練可能
- 1 epoch: 1000 枚で 10-30 分
- 必要 epoch: 50-100
- **総訓練時間: 約 1-2 日**
- ハイパーパラメータ探索を含めると 1 週間

### 出力品質の評価
- 訓練データの保留分 (10 %) で ratio 測定
- 我々のベンチ 13 画像でも測定
- **過学習を避けるため Poly Haven 以外の HDR も検証セットに含める**

### 失敗パターンと対策

| 失敗 | 兆候 | 対策 |
|---|---|---|
| 過学習 | 訓練データ 8x、検証データ 4x | データ拡張増、モデル小型化 |
| 汎化失敗 | 検証データのうち特定種が悪い | 訓練データに含める |
| 速度未達 | ANE で 50 MB/s 以下 | モデル小型化、量子化 |
| 決定性破綻 | 同入力で違う出力 | CoreML float32 強制、テスト追加 |

## 7. Quick Win プラン (1-2 週で見極め)

ML が本当に効くか早期判定するための最短経路:

### Quick Win 1: Python プロトタイプ (5-7 日)
1. PyTorch で軽量 CNN 残差予測器を書く
2. Poly Haven 100 枚で訓練 (1 時間)
3. rANS は既存 Python 実装 (constriction, arithmetic-encoder) を使う
4. 我々のベンチ画像で測定
5. **判定**: 6.0x ratio を超えれば本格実装、未達ならアーキ再考

### Quick Win 2: 「最小 ML」 実験 (3 日)
1. 既存 zstd の "predictor" 部分だけ ML 化
2. 残差予測ヘッドを zstd の出力に被せるだけ
3. 早期に「学習データ量がどれだけ必要か」が分かる

## 8. 古典版との関係

古典版 PLAN.md を「下位互換オプション」として残す:

| ビルド | 用途 |
|---|---|
| **古典版** (PLAN.md) | ANE が無い環境 (Linux サーバ等)、決定論性が最重要、6x で OK |
| **ML 版** (本書) | macOS/iOS、最大圧縮率、ANE 利用可能 |

## 9. リスクと対策

| リスク | 重要度 | 対策 |
|---|---|---|
| float32 HDR の訓練データが少ない | 高 | データ拡張 + tone mapping で合成 |
| ANE が float32 精度を保てない | 中 | float16 で訓練、量子化済みモデル、明示テスト |
| CoreML の決定論性が脆い | 中 | モデルを int8 量子化、bit-exact 検証 CI |
| モデルサイズが大きすぎる | 中 | 蒸留、深さ削減、知識蒸留 |
| 訓練が収束しない | 低 | 既存 L3C コードを参考に |

## 10. 進め方の提案

私の率直な推奨は **段階的 (古典→ML)**:

1. **古典版 Phase 0-4 を 4-5 週で実装** (5.5x baseline 確立)
2. これが動いたら **ML 版 Phase 5-9 を 6-7 週で追加** (7-9x へ)
3. 両ビルド維持

理由:
- ML 版がうまく行かなかった時のフォールバックが古典版
- 古典版の rANS、bitshuffle、色変換コードは ML 版でも 100 % 再利用
- ablation 比較 (古典 vs ML) で ML 寄与度を可視化できる
- 11-12 週は長いが、古典版 4-5 週時点で「Blosc 超え」の中間成果

代替案として **「いきなり Quick Win 1 で ML 試作」** もアリ:
- 5-7 日で 6.0x 出れば本気の ML 投資を正当化
- 出なければ古典に戻る

- (c) いきなり戦略 D で ML 全力 (8-10 週、リスク高)
